# Product tagline workflow

Use this workflow only for a text or visual hero. A description-led opening
does not need a separate tagline.

## Establish the message

Inspect repository and user-provided evidence for:

- the product category;
- the primary user;
- the outcome the product enables;
- a material design priority or differentiator;
- the established product voice and terminology.

Decide which one or two of these the tagline should carry. Let the literal
description supply anything the tagline intentionally omits. Keep the tagline
distinct from positioning: the tagline establishes identity, while positioning
explains several reasons to adopt the product.

## Draft candidates

When wording is neither canonical nor user-approved, propose a small set of
short candidates grounded in the evidence. Make the candidates differ on a
meaningful axis, such as category, audience, outcome, or product character;
do not offer cosmetic rewrites of one sentence.

Prefer wording that:

- is brief enough to scan as one unit;
- names a concrete category or outcome when possible;
- uses the product's own vocabulary;
- remains true without an unsupported superlative;
- sounds distinct from a generic feature description;
- still makes sense when separated from badges and imagery.

For each candidate, explain what it emphasizes and what the following literal
description would still need to clarify. Avoid slogans whose meaning depends on
wordplay, unexplained metaphors, or claims the repository cannot verify.

## Agree before drafting

Treat a tagline as settled only when the user has supplied or approved it, or
the repository clearly identifies it as canonical product language. Do not
silently select, invent, or preserve wording merely because it appears in an
existing README.

Pause before drafting the hero until the user chooses, revises, or explicitly
approves a candidate. Record the agreed wording in the reading contract.

## Place and verify

Keep the product name and tagline together in the selected hero treatment.
Follow a memorable but non-literal tagline with a plain sentence identifying
the product, primary user, and outcome.

Do not format the tagline as a blockquote. When a hero image also contains the
tagline, do not leave the wording only inside the image; preserve it as
accessible text or provide an equivalent literal description and meaningful
alt text.

In the final review, confirm that the tagline:

- matches the approved wording exactly;
- does not repeat the following description or positioning items;
- remains supported by current product evidence;
- fits the repository's visual and technical tone.
